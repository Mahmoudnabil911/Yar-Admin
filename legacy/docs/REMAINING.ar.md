# الملاحظات المتبقية - 9 نوفمبر 2026

هذه قائمة تسليم للمبرمج، وليست ميزات مكتملة في النموذج الحالي.

## نقاط تحتاج قرارًا من الإدارة

- **مدة وسعر الباقة:** عمود القائمة أصبح «عدد الأيام»، لكن حقول خيارات الفندق والبنرات ما زالت تعتمد `price5USD` و`price7USD`. يلزم اعتماد نموذج مدة/سعر مرن، ثم ترحيل السجلات والمحتوى واختبارات التطبيق معًا. لا تُستنتج أيام الباقة تلقائيًا من الليالي.
- **الخصومات:** اعتماد سياسة الحد الأدنى للسعر أو موافقة المدير عند انخفاضه عن تكلفة المورد؛ المحاكي الحالي يبيّن الأثر ولا يمثل موافقة تجارية.
- **الاسترداد والإلغاء:** اعتماد سياسات المورد ورسوم الإلغاء والمدة المسموحة والموافقات المطلوبة. إلغاء الحجز لا يرد المال أو رصيد المورد تلقائيًا.
- **العملات:** تحديد المصدر الرسمي لسعر الصرف عند الحاجة والموافقة عليه؛ لا يوجد صرف آلي في النموذج. فصل أرصدة كل مورد وعملة قائم.
- **الأرصدة:** تثبيت تسمية المدين/الدائن مع المحاسب وربط كشف المورد بالدفتر المحاسبي؛ المثال الحالي كشف تشغيل وليس دفتر حسابات إنتاجيًا.
- **الصور والأسعار:** توفير صور الموردين المعتمدة والأسعار والمخزون الحقيقي وحقوق الاستخدام بدل صور وأرقام المثال.

## ما ينفذه الفريق البرمجي

1. خادم وقاعدة بيانات ومصادقة وإدارة جلسات وصلاحيات مفروضة على الخادم، مع نسخ احتياطية وسجل تدقيق.
2. عقد بيانات موحد بين لوحة الإدارة وتطبيق المسافر. «نشر في المعاينة» لا ينشر حاليًا إلى تطبيق Expo.
3. موصل مستقل لكل API طيران، وتوحيد الرحلات والأسعار والتفاصيل ومراجع الموردين، وإعادة التحقق قبل الإصدار.
4. عمليات آمنة عند التزامن وإعادة المحاولة: منع تكرار الدفع والإصدار وخصم الرصيد، ومعاملة ذرية للحجز والدفتر المالي.
5. بوابات دفع فعلية وWebhooks موثقة التوقيع والمبلغ والعملة والمرجع. سجل البوابات التجريبي الحالي مستقل عن التحصيل الفعلي للحجز.
6. ربط الشحن والخصم وإرجاع الرصيد مع المورد وتوثيق كل مرجع وPNR والمسار، دون كشف مفاتيح الربط للمتصفح.
7. تتبع أحداث حقيقي بمعرفات مستقلة للحدث والجلسة والبحث والطلب؛ لا بيانات جوازات أو أرقام هواتف في أحداث التحليل.
8. نشر محتوى وإشعارات وربط واتساب وفق الإجراء الذي يؤكده المستخدم، بدل سلوك المعاينة المحلي.
9. فحص الوصولية والمتصفحات والاستجابة وسلوك الفلاتر وحالات التحميل والفراغ والأخطاء قبل الإطلاق.

## تفاصيل معروفة في المصدر الحالي

- مخطط الحركة الأسبوعية القديم في نظرة عامة توضيحي مستقل؛ تقارير العمليات تعتمد سجل الطلبات، وتقارير السلوك تعتمد أمثلة أحداث مستقلة.
- حالة الدفع لا تظهر كعمود في جدول «الحجوزات والطلبات»، لكنها باقية في ملخص «آخر الحجوزات» وداخل التفاصيل.
- أُلغي «مرفوض» من حالات الحجز؛ رفض إيصال الدفع ما زال موجودًا. التاريخ القديم محفوظ ولا يعاد كتابته.
- أزيل قسم المستندات من واجهة الحجز، لكن نموذج البيانات قد يحتفظ بالمستندات وأحداثها التاريخية.
- الإسناد والملاحظات محليان؛ عرض توقيت سجل المتابعة الحالي بصيغة ISO/UTC يمكن تحسينه إلى تنسيق عربي بتوقيت بغداد.
- تعريف «معدل إرسال الطلب» يختلف عن «تحويل إلى حجز مؤكد». فترة تقرير العمليات حسب تاريخ إنشاء الطلب، وفترة عمليات البوابة حسب تاريخ العملية.
- رسوم البوابة على الشركة لا تُضاف تلقائيًا لسعر الزبون، ولا تعيد تسعير حجوزات قديمة.
- بعض تواريخ HTML القديمة تتحدث عند تشغيل JavaScript؛ يعتمد عرض اليوم وتوليد أمثلة البداية على تاريخ أول تشغيل ويوم بغداد.

## حدود الحزمة

الكود الحالي والأصول وبيانات المصدر التجريبية مرفقة. لا توجد قاعدة بيانات أو سجل المتصفح المنشور أو مفاتيح API أو كود React Native أو جلسات دخول. الصور الخارجية التسع أُرفقت محليًا، ومساراتها وحدها جرى تكييفها مع قائمة قبول محلية محددة ولقطة اختبار مقابلة. راجع `ASSET-MANIFEST.json` و`reference-source/` للمقارنة بالمصدر قبل التغليف.
